# 技術與流程決策紀錄

原始英文紀錄保留於初始 commit；以下為保留原意的繁體中文版本，新增決策以新編號追加。

## ADR-001：Web 優先（既有決策）

採 TypeScript／Three.js／Vite 桌面瀏覽器，先於 Unreal。理由是快速迭代與互動驗證；取捨為高階光影的實際上限低於大型原生引擎。

## ADR-002：先占位驗證（既有決策）

P1 使用幾何人物，P3 換成合法高品質骨架 GLB。分開操作驗證與美術資產工作，占位人物不作最終品質驗收。

## ADR-003：Git 保存工程記憶（既有決策）

以 commits、AGENTS 與規格／進度／決策文件延續工作。Git 不會自動保存全部聊天與內部思考。

## ADR-004：通用流程與遊戲規格分開（2026-10-22）

採 WORKFLOW 與研究模板作可複用制度，MASTER_PLAN 保留遊戲範圍。比單一巨型 AGENTS 更便於複用；代價是需檢查跨文件一致性。初版稱 v0.1，完成實際遊戲任務閉環後才評估 v1.0。

## ADR-005：可追溯證據與繁體中文（2026-10-22）

先提交計畫，保存失敗、更正及受測版本；中文 Commit 說明、PR 與報告方便研究者閱讀。保留原始技術訊息與英文識別字便於搜尋。採 merge commit 保留中間 commits，不 squash 研究歷史。

## ADR-006：分階段啟用 CI（2026-10-22）

本任務先驗證無第三方依賴的文件檢查。遊戲缺依賴與 lockfile，且有已知重生程式問題；遊戲 CI 在 task-002 實測後加入，文件綠燈不代表遊戲完成。禁止以略過失敗檢查偽裝完整 CI。

## ADR-007：依工作大小簡化流程（2026-10-22）

使用者要求本次直接更新，避免制度過重。文件整理與小修改可直接提交 main，只需清楚的變更說明與相關驗證；正式遊戲任務保留研究紀錄，較大功能使用分支／PR。使用者的明確範圍與授權優先，不為流程本身製造工作。

## ADR-008：所有任務直接更新 main（2026-10-22，取代 ADR-007 的分支規則）

使用者進一步明確要求所有任務均不使用分支。統一在 main 開發、提交與推送，不建立 PR；移除 PR 模板，CI 只監聽 main 推送。保留中文 commits、正式任務研究紀錄及必要驗證。若遠端保護阻止直接推送，回報阻塞，不繞過限制。舊任務中的分支紀錄僅描述歷史，不作後續規則。

## ADR-009：型別化生命週期與最小可觀測性（2026-10-22）

task-002 將怪物 HP 與重生排程從無型別 userData 抽出為小型模組；死亡瞬間只排程一次，死後命中無效。Node.js 24 內建 TypeScript 執行與 test runner 減少單元測試依賴；Playwright 負責真實瀏覽器回歸。只在 ?debug=1 提供回傳副本的狀態快照，無遊戲狀態修改入口。完整系統拆分留下一項任務。

## ADR-010：以遊戲時間量測操作（2026-10-22）

雲端軟體渲染與跨程序通訊會延遲鍵盤指令；速度測試在按鍵持續按下期間取兩次位置／遊戲時間，冷卻檢查在命中影格內同步派送重複事件。保留相同功能斷言，不將輸入傳送耗時誤判為遊戲速度錯誤。遊戲仍使用既有 dt 上限，低 FPS 時遊戲時間可能慢於牆鐘時間，P2 再處理時間步進。

## ADR-011：依使用者展示回饋提前人物品質（2026-10-22）

使用者指出積木主角無法呈現品質，要求先換角色並可拉近查看。P3 第一版提前：GDQuest Sophia 具臉髮、服裝貼圖與完整骨架，2.6 MB 適合小型網頁研究。使用者明確確認非商業研究用途，保存 BY-NC-SA 4.0 原文、固定來源版本與雜湊。此為風格化改善版，寫實目標仍未完成。

## ADR-012：可拉近環視的鏡頭與本地資產（2026-10-22）

鏡頭抽為模組，預設距離 7.5、滾輪範圍 2.5–24，近距離降低俯角並把目標移到上半身；右鍵環視、R 重設。移動以目前鏡頭方位計算。GLB 與來源說明放 public，URL 使用 Vite BASE_URL，實測 /canopy/ 子路徑，方便 XAMPP 展示。

## ADR-013：非同步載入的首影格與動畫限制（2026-10-22）

載入模型後原本 performance.now 初始化可能大於首次 RAF timestamp，造成負 dt 與錯誤攻擊狀態。首影格 dt=0，其餘夾在 0–0.045，新增單元回歸。debug frame 改計真正遊戲 render 次數，不含環境貼圖生成。
原始資產沒有 Walk 或 Attack clip：目前步行為 Run 調速，攻擊為手臂／胸部骨架疊加，劍連在手骨上。明列限制，不假稱為專業動捕或最終動畫驗收。

## ADR-014：可比較的三角色展示與可重建資產（2026-10-22）

使用者要求自行尋找更好的人物並可選擇展示。實際近看後淘汰低面數 HVGirl，採 Rocketbox 男女各一位自然比例人物，加上既有 Sophia 作風格比較。保存固定版本、來源及改作流程，新增約 11.8 MB 本地資產，按需載入；不擴大場景。人物庫明確 MIT，非僅推論程式碼授權可套用資產。Blender 世界空間骨架轉移處理不同休止姿勢，不直接複製局部旋轉。

角色載入採最後請求優先，成功才替換、失敗保留原角色；卸載時釋放 Mixer／幾何／骨架／材質／貼圖。展示模式暫停遊戲時間與戰鬥，實際播放骨架動畫；展示時間與遊戲時間分離，退出可恢復操作。最近鏡頭調至 1.5；寫實人物近看採距離 1.5／焦點 1.9，Sophia 大頭比例採 2.5／1.65，避免共用近看設定裁臉。保留最大距離與預設距離。

## task-005：多骨架重新綁定與逐角色移動速度（2026-10-22）

- 不同來源骨架（UE5／Mixamo／QuickRig／Blender IK／Character Creator／自訂）以 Node + three.js 離線烘焙同一組動畫，遊戲端維持普通 AnimationMixer；不在執行時重新綁定。
- 朝向以左右大腿判定（持武器 rest 姿勢的雙臂不可靠），統一旋轉至 +Z 以符合 `atan2(vx, vz)`。debug 快照提供解剖正面，供方向回歸。
- 移動速度改為逐角色設定：新角色依動畫著地腳速度（Walk 1.85、Run 3.2）取 2.4／5.2，既有三角色維持 4.3／8。
- 素材以 docs/asset-catalog/catalog.json 為唯一總表，原檔只記雜湊不入庫。

## task-006：測試分層與揮劍改為角色座標（2026-10-22）

- 逐角色瀏覽器測試（每位 2–4 分鐘）改為 Node 單元測試：以遊戲同一個 GLTFLoader 解析 GLB（去除貼圖），用 AnimationMixer 取樣檢查骨頭、動畫、正面、步態、滑步與揮劍方向。瀏覽器只保留整合路徑。
- 瀏覽器測試分 @smoke 與完整兩層；同骨架同設定的重複情境（男／女）不重複測。
- 揮劍程序姿態改以角色座標定義並換算到骨頭，不依賴骨架本地軸；加入姿勢還原器，因 AnimationMixer 在數值未變時不重寫骨頭，程序疊加會累加。正式攻擊動畫到位後仍應取代。

## task-007：Mixamo 動作層（2026-10-22）

- 一次性動作（攻擊、施法、受擊、倒地）由 hero 動作層播放，期間鎖定移動；傷害依各動作擊中時刻（右手相對骨盆速度峰值）判定，不再用固定 0.32 秒程序揮劍。
- 操作：J 單擊、K 二連擊、L 三連擊、Q 施法、C 蹲走。只有 Mixamo 動作組角色啟用；舊角色維持原行為與測試。
- 玩家 HP 歸零時倒地並於動作結束後 1.5 秒重生（先前未實作玩家死亡）。
