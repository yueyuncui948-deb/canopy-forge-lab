# 通用自主開發與研究流程

## 授權、任務與語言

使用者決定研究目標與授權範圍。Agent 在範圍內自主規劃、實作、驗證、修正與記錄，遇到必要權限或重大範圍變更才提出具體問題。
正式遊戲任務建立 task-NNN 紀錄；可另建 GitHub Issue，但本地唯一編號已足以識別。文件整理與小修改可直接更新 main，使用清楚的 commit 與必要驗證即可，不必為每次小修改建立五份報告。較大功能使用 task-NNN-short-description 分支與 PR。Commit 如 fix: 修正怪物死亡後無法重生；PR、報告及說明使用繁體中文。

## 標準循環

1. 讀取規格、目前進度與 Git 狀態，定義本次目標及不包含的工作。
2. 正式功能任務建立分支與 PLAN.md，記錄方案、選擇理由、假設及驗收標準；文件整理可直接在 main 記錄並提交。
3. 實作最小可驗證變更，記錄操作、修改檔案與問題。
4. 執行符合風險的檢查，保存退出碼、測試數量、原始輸出與受測版本。
5. 自我審查；獨立 reviewer 可用時另記來源、工具及是否共用模型／上下文。
6. 修正並重跑受影響檢查。每個修正嘗試要有假設與新證據。
7. 正式功能任務完成五份研究紀錄、更新進度及必要決策／資產資料，提交並建立 PR；小型文件修改直接提交。
8. 使用 PR 時，核對最終版本、遠端檢查、審查與分支保護後才合併；直接提交也必須執行適當檢查，不繞過分支保護。

使用現有隔離 checkout；除非使用者明確要求，不建立 worktree。原始失敗的事前計畫與研究證據不得回寫成成功；更正追加日期、原因及取代關係。

## 測試證據契約

每份報告記錄 commit、工作目錄是否乾淨、未提交變更的 diff SHA-256、時間與時區、工具版本、工作目錄、實際指令、退出碼、結果及證據路徑。對未提交版本保存 diff 證據時先檢查是否包含敏感內容。
若報告本身在測試後才加入，說明其為文件追加；程式變更後重跑受影響檢查，不沿用舊結果。測試框架需記錄 passed／failed／skipped 數量，零測試不是驗證成功。
commands.jsonl 每行可使用欄位 time、cwd、command、exit_code、tested_commit、dirty、evidence。僅記錄實際已執行的指令；不得事後偽造精確時間或補造原始輸出。
憑證、環境變數值及私人資料需遮蔽；不要傾印環境或 credential 檔案。大型影片、模型另設受控保存方式，Git 留來源與雜湊；必要研究證據不可只放會過期的 CI artifacts。

## 分層驗收

| 層次 | 必須確認 | 不能據此宣稱 |
|---|---|---|
| 文件 | 必要檔案、連結、規格一致性 | 遊戲功能正確 |
| 程式 | 型別、建置、相關單元／整合測試 | 畫面精緻或操作流暢 |
| 瀏覽器 | 真實 WebGL、輸入、狀態變化、錯誤與截圖 | 單張截圖足以驗證整套動作 |
| 視覺 | 人物、動畫、光影、構圖，列出評估者與依據 | 完全客觀的美術分數 |
| 效能 | 裝置、GPU、瀏覽器、解析度、情境、平均 FPS、1% low | 軟體渲染 FPS 等於實體 GPU 表現 |

狀態使用：通過、失敗、阻塞、未執行、不適用。功能實作但未測試仍須標記未驗證。SwiftShader 是實際軟體渲染，不是假畫面，但不能用於目標 GPU 的效能驗收。

## 重試與阻塞

同一問題最多三次有不同診斷依據的修正嘗試；不重複執行未改變條件的失敗命令。仍未解決時，保存最小重現、嘗試、原因及替代方案，將依賴工作標為阻塞，繼續可獨立完成的工作。新的外部條件或明確新證據可開啟後續任務並連結原紀錄。

## CI 與合併門檻

母版 v0.1 僅啟用文件 CI。task-002 應建立並驗證 lockfile、npm ci、型別及建置流程，再加入遊戲 CI；後續依實際測試套件加入相關工作。既有建置失敗需如實記錄，不能用文件 CI 綠燈代替遊戲驗收。
文件任務以文件檢查為門檻；遊戲任務另需建置、型別與相關功能測試。遠端檢查必須對應 PR 最終程式版本，必要檢查全通過、無未解決阻斷問題且符合分支保護才能合併。沒有設定遠端 required checks 不代表可略過本地驗收。
缺少獨立審查時標記未執行；若分支保護要求審查就保持待審，不能自行替代。缺少 API／push 權限時保存本地結果，精確區分已提交、已推送、PR 已建立、CI 已通過及已合併。
採用保留 commits 的 merge commit；不 squash、不 rebase 已分享歷史、不強制推送。自動合併僅在所有門檻已證實且權限允許時進行。

## 完成與報告

SUMMARY 記錄完成範圍、未完成項目、commit／PR、測試證據、風險與下一項任務。工程決策紀錄提供可核對的理由與觀察，不宣稱是 Agent 內部思考的逐字記錄。
