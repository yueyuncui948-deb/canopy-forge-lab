# 執行紀錄

## 實際過程

1. 讀取工作規則、現有主角／鏡頭／測試及來源文件，工作目錄原本乾淨，直接在 main。
2. 建立 PLAN，再實作角色清單、通用骨架設定、可切換人物面板、展示暫停及視角預設。
3. 試載 Babylon.js HVGirl；真實近看發現低面數切面，不符合使用者要求。保留淘汰截圖，移除候選資產，不放進最後選單。
4. 找到 Microsoft Rocketbox，核對上游 README 明確的 MIT 人物授權，下載固定版本男女各一位及各自 Idle／Walk／Run，保存每個來源雜湊。
5. Blender 檢查發現 FBX 貼圖引用無效絕對路徑，且人物與動畫休止姿勢不同（右上臂旋轉差約 0.776 radians）；不能直接套局部旋轉。重建材質，世界空間轉移旋轉並烘焙 NLA，骨盆僅保留垂直位移，原地化走跑。
6. 初始 GLB 約 12 MB／10.7 MB。Blender 設定 JPEG 未讓 exporter 將底色實際改為 JPEG，檢查 GLB mimeType 後新增明確編碼腳本；最終女 6.16 MB、男 5.60 MB。保留法線與頭髮透明 PNG。
7. 實際近看確認臉部／服裝細節，再把最短距離由 2.5 改成 1.5，近看目標提高至 1.9。原測試寫死 MIN_DISTANCE > 2 因需求變更失敗；保存原始結果，改成驗證新明確範圍，穿模另以實際畫面檢視，沒有把數值斷言當成視覺證明。
8. 自我審查修正：展示切換核取方塊保有焦點時，WASD 仍應恢復遊戲；只攔截其 Space／Enter，保留一般鍵盤控制。短視窗選角面板改為可捲動，避免底部功能被裁掉。

## 補測失敗與修正

移除測試內手動 blur 後，補測發現 WASD 已恢復，但 Space 仍觸發核取方塊而非跳躍（高度一直為 0）。這是實際焦點問題，不調低跳躍斷言；改為退出展示時將焦點明確交回可聚焦的遊戲 canvas，保留展示開啟時的 UI 鍵盤操作。失敗截圖、trace、原始結果保存於 evidence/focus-failure 與 browser-focus-failure.json，重新執行受影響測試。

子路徑 smoke 首次在檢查來源連結時出現 APIRequestContext.get: Invalid URL：測試 API 未設定 baseURL，卻直接使用 HTML 中的相對 href。遊戲與人物當時已成功載入。測試改讀瀏覽器解析完成的絕對 link.href，保留原始 subpath-smoke.log，重跑相同 HTTP 200 與三角色載入斷言，沒有修改應用程式來規避失敗。

## 最終視覺更正

/canopy/ 三角色載入與來源連結通過，但逐張人工式檢視截圖後，Sophia 在寫實人物的 1.5 距離／1.9 焦點下臉部被裁切。保留原始裁切截圖，新增角色比例設定：寫實近看 1.5／1.9，Sophia 近看 2.5／1.65；切換時保留近看意圖。滾輪仍可手動深入檢視，不改原最大／預設距離。這是程式測試通過仍不等於視覺驗收的實際例子，另重跑切換與子路徑實際截圖。
